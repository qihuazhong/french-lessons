# Proposal — `parcours.html`: CEFR grammar roadmap with personal mastery

Status: draft for review · 2026-11-10

## 1. What exists today (review)

| Area | Current state | Consequence for a roadmap |
|---|---|---|
| Site | Static GitHub Pages, pages generated by Python (`tools/*.py`), shared JS (`srs.js`, `exos.js`) | Roadmap should be a generated static page + small client script. No framework. |
| Grammar points | 34 `<h3>G#</h3> + .gram-box` blocks across 4 lessons, levels A2–C1 | No A1 and no C2 content yet. |
| Grammar identity | Key = `gram:<level>:<G#>`, local to each lesson | **No shared concept ID.** The same point appears several times: *y/en* (ai B1, dommage A2, opinions B1), *conditionnel passé* (dommage B1, opinions B2), *questions est-ce que* (ai A2, france A2), *subjonctif* (opinions B2, france B2). |
| Level consistency | *y* is A2 in dommage, B1 elsewhere; *conditionnel passé* is B1 in one lesson, B2 in another | A lesson's level is "the parcours where it's taught", not the CEFR level of the concept — the roadmap needs its own canonical level. |
| Exercise signal | `exo-graded` event → activity `{k:'exo', lesson, id, score, total}` | Exercise IDs (`ai-b1-2`) are not linked to grammar points; exercises mix vocab and grammar. |
| SRS signal | Grammar cards in deck with `st, ivl, reps, lapses, last` | Best retention signal — but only for points the learner chose to add. |
| Activity log | Capped at 800 entries, dominated by `rev` events | Exercise history older than ~800 reviews is lost → can't be the long-term mastery store. |
| "Logged in" | Google ID token in `fr-lessons-session`; progress synced to Worker/D1 as one JSON doc | Progress also exists **locally without login** (localStorage-first). |

## 2. Proposed design

### 2.1 Canonical curriculum — `content/curriculum.json` (source of truth)

A CEFR inventory independent of lessons (seeded from the CECRL / *Référentiel
de français* inventories), ~15–25 points per level, A1→C2:

```json
{ "id": "pron-y-en", "level": "B1", "cat": "Pronoms",
  "title": "Les pronoms y et en",
  "summary": "Remplacer un complément introduit par à / de.",
  "prereq": ["pron-cod-coi"] }
```

Categories (stable chips/filters): Le verbe et les temps · Modes ·
Pronoms · Déterminants · Négation · Questions · Phrase complexe (cause, but,
concession…) · Discours & registre.

### 2.2 Tag the content (small, mechanical authoring change)

- Grammar point: `<h3 data-gp="pron-y-en">G1 — Les pronoms y et en</h3>` in `src/part4.html`.
  A lesson point may map to several concepts (`data-gp="cond-passe regret"`).
- Exercise: `"concepts": ["pron-y-en"]` in the exo JSON spec (block level).
  Optional later: per-item `"c"` tag + per-item results in the event, for mixed exercises.
- `tools/build_roadmap.py` + test: every `data-gp` / `concepts` value must exist in
  `curriculum.json`; report curriculum points with no lesson coverage.

The existing SRS key `gram:<lv>:<G#>` stays unchanged (no migration); the
roadmap resolves card → concept by reading `data-gp` at build time into a
lookup table `{ "lecon-ai.html|gram:b1:G1": ["pron-y-en"] }` embedded in the page.

### 2.3 Page — `parcours.html` (generated)

- Six level columns/tabs A1…C2, each a list of concept cards grouped by category.
- Each card: title, one-line summary, and **« Étudier dans : »** links to every
  lesson covering it (`lecon-ai.html#grammaire` + preselect the level via
  `?niveau=b1` — tiny addition to `framework/script.html`). Uncovered points
  show « Bientôt » (honest about A1/C2 gaps).
- Linked from `index.html`, side panel nav, and `progres.html`.
- Fully static & readable without JS → generic mode is free.

### 2.4 Personal mode (signed in)

`mastery.js` (or a `SRS.mastery(doc, map)` pure function — testable in `test_srs.js`):

Evidence per concept:
1. **Practice** — exercise attempts on tagged exercises: recency-weighted accuracy
   of the last 5 attempts (weights 1, .8, .6, .4, .2; `almost` counts as 0.5).
2. **Retention** — linked grammar SRS cards: interval, lapses, last review.
3. **Exposure** (optional, cheap) — record `{k:'seen', lesson, lv}` when a
   grammar block is shown; only lifts "Non commencé" → "Découvert".

Levels (5 states, colour ramp, legend on page):

| State | Rule (first match from the top) |
|---|---|
| Maîtrisé | accuracy ≥ 85 % over ≥ 2 attempts **and** a linked card with `ivl ≥ 21 j` — *as built: or ≥ 3 attempts ≥ 90 % spread over ≥ 7 days (so learners who never add grammar cards can reach it); card alone caps at Acquis; the "no lapse in 30 j" clause was dropped (lapse dates aren't stored)* |
| Acquis | accuracy ≥ 80 % over ≥ 2 attempts, **or** a linked card with `ivl ≥ 7 j` |
| En cours | any attempt or card in learning/review |
| Découvert | only exposure / card added, never reviewed |
| Non commencé | no evidence |

Decay: evidence older than 90 days drops one state ("à revoir") — the roadmap
then nudges the learner instead of showing stale green.

*As built:* « À travailler ensuite » starts at the learner's current level
(highest level with at least 2 points « En cours » or beyond, so one
exploratory exercise doesn't move it), not at A1.

Level summary at the top of each column: `7/18 acquis · 3 à revoir` and a
progress bar; "Next up" = first non-acquired concept whose prereqs are acquired.

### 2.5 Data-model change (required for durable mastery)

Add to the progress doc a capped-per-exercise attempt store, separate from the
800-entry activity log:

```js
doc.exo = { "lecon-ai.html|ai-b1-2": [{t, last, score, total, almost, partial?, retries?}, …last 10] }
```

Implemented (step 3), refined in step 4 after review: every exercise type shows
corrections before a sheet is complete (fill/match on « Corriger », choice on
each pick), so scores are **first-try**: exos.js fixes each item's verdict when
its answer is first revealed and reports `first`; one attempt = one sitting (an
exos.js round, or a redo < 15 min later) and its score is that first try;
re-checks and immediate redos count as `retries`. Mastery should use
complete attempts' scores (first-try accuracy) and may treat many retries as a
weak negative signal. Merge = per attempt start `t`, most advanced version
wins; backfill from legacy `activity` entries on load and merge, idempotent.
Worker/D1 need no change (doc is opaque JSON).

Exercises carry `"concepts": [...]`; 26/38 practise grammar, 12 are vocabulary
only. 8 taught points have no exercise yet (opposition, but, nuancer son
opinion, verbes d'opinion, négations jamais/rien, intonation, effacement de
l'agent, mise en relief) — for those, mastery relies on review cards.

### 2.6 Logged-in vs generic

**Decision (2026-11-10): the overlay shows whenever progress data exists,
signed in or not.** Signing in only adds cross-device sync.

- No local progress and not signed in → generic roadmap (static page as-is) +
  a short line linking to the lessons and to sign-in on `progres.html`.
- Local progress, not signed in → overlay from the local doc + a discreet
  « Connectez-vous pour retrouver vos progrès sur tous vos appareils ».
- Signed in → render the overlay from the local doc immediately, then
  `SRS.syncNow()` and re-render if the merge changed anything.
- « Masquer ma progression » toggle (remembered in localStorage) to see the
  generic roadmap on demand.

## 3. Implementation plan (incremental, each step shippable)

1. ✅ (2026-11-10) `content/curriculum.json` A1–C2 + `data-gp` tags on the 34 existing points + coverage test.
2. ✅ (2026-11-10) `tools/build_roadmap.py` → static `parcours.html` (generic), nav links, `?niveau=` support.
3. ✅ (2026-11-10) `doc.exo` store + merge + backfill in `srs.js`; `concepts` tags on exercises; tests.
4. ✅ (2026-11-10) `SRS.mastery()` + overlay rendering + sign-in banner; tests on the rules table.
5. Optional: per-item exercise tagging, exposure events, "next up" recommendations.

## 4. Risks / notes

- Curriculum authoring is the real work (≈120 points); worth doing once, carefully.
- Mastery from 2–3 exercises per concept is thin — show evidence on hover
  ("2 exercices · 1 carte, intervalle 9 j") so the label is explainable.
- Keep the rules in one pure function so thresholds can be tuned without UI changes.
